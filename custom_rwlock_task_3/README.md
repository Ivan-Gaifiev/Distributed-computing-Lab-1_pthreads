# rwlock и односвязный список

Сравнение собственной блокировки чтения-записи с `pthread_rwlock_t` на C11.
Поиск в списке использует блокировку чтения, вставка и удаление — записи.
В собственной реализации ожидающие писатели имеют приоритет перед новыми читателями.

## Сборка и тесты

Нужны GCC с pthreads, GNU Make и Python 3.9+. Для Windows — MSYS2 MinGW-w64,
каталог `mingw64/bin` должен быть в `PATH`.

```powershell
mingw32-make
mingw32-make test
```

В Linux:

```sh
make
make test
./rwlock_bench --lock custom --threads 4
```

## Запуск

```powershell
.\rwlock_bench.exe --lock custom --threads 4
.\rwlock_bench.exe --lock pthread --threads 4
```

По умолчанию список содержит 1000 ключей, выполняется 100000 операций:
90% поисков, 5% вставок и 5% удалений. Изменить нагрузку можно так:

```powershell
.\rwlock_bench.exe --lock custom --threads 8 --initial 100 --ops 100000 --read 0.5 --insert 0.25
```

Доля удаления — остаток после поиска и вставки. Параметр `--seed` задаёт
начальное состояние генератора, `--key-range` — диапазон ключей.
Полная справка: `--help`. В Linux имя программы — `./rwlock_bench`.

Результат выводится одной строкой CSV без заголовка: параметры запуска,
счётчики операций, итоговая длина списка, контрольная сумма нагрузки,
время в секундах и операций в секунду. Ошибки выводятся в stderr.

## Замеры

```powershell
mingw32-make benchmark
```

Сценарий проверяет оба режима на списках из 100 и 1000 элементов, с разными
долями чтения и записи, на 1, 2, 4 и 8 потоках. Для каждой конфигурации —
один прогрев и 10 измерений. Подготовка данных, создание потоков и вывод
в измеряемое время не входят.

Результаты сохраняются в `results/`, сводка — в [summary.csv](results/summary.csv).
Алгоритм, методика и выводы — в [отчёте](REPORT.md).

В сводке: ускорение `S = T1/Tp` и эффективность `E = S/p`, где `p` — число
потоков. `T1` и `Tp` — медианы времени для того же режима и нагрузки.
В CSV эффективность записана долей, в отчёте — процентами.

`metadata.json` с характеристиками компьютера и локальными путями остаётся
только на машине и не добавляется в Git.

Сохранённые результаты не перезаписываются. Для повторного замера укажите
новый каталог:

```powershell
python run_benchmarks.py --output results-repeat
```

В Linux: `make benchmark`, а для нового набора —
`python3 run_benchmarks.py --output results-linux`.

## Графики

Нужен Matplotlib. Из корня репозитория:

```sh
python -m pip install -r custom_rwlock_task_3/visualization/requirements.txt
python custom_rwlock_task_3/visualization/plot_results.py
```

PNG сохраняются в `visualization/figures/` и вставляются в отчёт.
После новых замеров выполните скрипт снова; для другого набора есть
`--results`, `--output` и `--report`. В Linux используйте `python3`.
