## Что реализовано

Гравитация в 2D, G=6.67430e-11 м³/(кг·с²). Для каждой пары i<j один раз вычисляется F=G*m_i*m_j*(r_j-r_i)/|r_j-r_i|³; силы добавляются с противоположными знаками. Явный Эйлер: r_new=r_old+h*v_old, v_new=v_old+h*F_old/m. Шаг 3600 с, последний шаг сокращается.

Рабочие потоки создаются один раз. У каждого массив N векторов сил. Главный суммирует частные силы. Эйлер выполняется рабочими над непересекающимися наборами тел. Четыре барьера отделяют старт шага, готовность сил, разрешение обновления тел и готовность координат. CSV пишет главный. После остановки выполняются join, освобождение памяти и уничтожение барьеров. Время пар O(N²), частные силы занимают O(PN) памяти.

Основной lab_1_2_solution.c — основная версия программы для вычислений; в этой работе вычислительное ядро не оптимизировалось. serial_baseline.c — отдельная последовательная версия для сравнения, без pthreads; та же формула, порядок Эйлера, шаг и формат CSV. Это эталонная версия

## Сборка и запуск

GCC с pthreads (Linux либо MSYS2 UCRT64 в Windows):

```sh
gcc -O2 -std=c11 nbody.c -o nbody -pthread -lm
gcc -O2 -std=c11 serial_baseline.c -o nbody_serial -lm
```

Windows: можно явно указать выходы nbody.exe и nbody_serial.exe. Каталог MSYS2 UCRT64/bin должен быть в PATH для DLL. pthread_barrier_t требуется от используемой реализации pthreads; штатный macOS pthreads его не предоставляет.

```powershell
.\nbody.exe solar_system_2d.txt 31557600 4
```

Аргументы: input.txt t_end threads. Время в секундах. Результат output_coordinates.csv записывается в текущую папку и перезаписывается следующим запуском. Формат без заголовка: t;x1;y1;...;xN;yN. Начальная строка t=0 включена. Массы в кг, координаты в м, скорости в м/с; вход: N, затем N строк m x y z vx vy vz. В 2D z=vz=0.

## Генерация большого входа

```sh
python generate_bodies.py 4096 bodies_4096.txt --seed 42
```

Сетка с небольшим случайным смещением исключает совпадающие начальные положения. Шаг сетки 1e10 м, массы 1e20..1e22 кг, компоненты скоростей -100..100 м/с. Seed обеспечивает повторяемость. Это искусственная нагрузка для замеров, не модель Солнечной системы и не гарантия устойчивости на длительных интервалах.

## Повторение замеров

Python 3; генератор и benchmark используют только стандартную библиотеку:

```powershell
python benchmark.py --exe .\nbody.exe --serial .\nbody_serial.exe --sizes 256 1024 4096 --threads 1 2 4 8 --steps 24 --repeats 3 --out results_new
```

Один прогрев каждого варианта, затем три измерения; порядок вариантов перемешивается фиксированным seed. Запуски идут последовательно, отдельная папка на запуск предотвращает перезапись результатов другим процессом. В сводке медиана, минимум, максимум и T_serial/T_parallel. Raw-файл содержит каждое измерение. Временные CSV после проверки удаляются, исходные наборы сохраняются. Проверяются форма CSV, конечное время, конечность всех значений и каждая координата относительно последовательного расчёта: |a-b| <= 1e-3 м + 1e-12*max(|a|,|b|).

## Фактический отчёт о замерах

Windows 11 x64, AMD64 Family 25 Model 80 Stepping 0 (AuthenticAMD), 12 логических процессоров. GCC 16.2.0 MSYS2 UCRT64, -O2 -std=c11, без fast-math. 24 шага по часу, 25 строк данных; 3 измерения на вариант. Таймер Python perf_counter измеряет полное время дочернего процесса, включая запуск, чтение, память, вычисления, синхронизацию, CSV и завершение. Запись до закрытия файла, без принудительного сброса дискового кэша. Фоновая нагрузка ОС возможна; измерения описывают фактическое время в этой среде.

| N | Sequential, s | 1 thread, s | 2 threads, s | 4 threads, s | 8 threads, s | Best speedup |
|---|---:|---:|---:|---:|---:|---:|
| 256 | 0.0392 | 0.0466 | 0.0425 | 0.0465 | 0.0437 | 0.92x |
| 1024 | 0.1944 | 0.1881 | 0.1494 | 0.1223 | 0.1049 | 1.85x |
| 4096 | 2.5901 | 1.9451 | 1.1537 | 0.7647 | 0.6017 | 4.30x |

На 256 телах затраты запуска, барьеров и ввода-вывода превышают выигрыш. Для 4096 тел восемь рабочих ускорили полный запуск в 4.30 раза относительно отдельного последовательного эталона. Относительно pthreads с одним рабочим ускорение около 3.23 раза. Эти сравнения различаются: отдельные функции и структура циклов могут по-разному оптимизироваться компилятором. Один рабочий не является безусловным эквивалентом последовательной реализации. Три запуска дают ориентир на этой машине, не универсальный показатель. Суммирование сил остаётся последовательным, CSV и барьеры ограничивают масштабирование.

Все 45 измеряемых запусков и 15 прогревов завершились успешно. Координаты в сохранённой точности CSV совпали с последовательной версией во всех нагрузочных тестах. Это не доказательство побитового равенства внутренних double для любых данных. Дополнительно проверены 9 тел на 1/2/4 потоках, конечный момент 5400 с, t_end=0, столкновение без зависания, повторяемость генератора. Протокол: results/tests.txt. Детектор гонок не запускался, отказ pthread_create искусственно не моделировался.

## Источник данных Солнечной системы

Данные по планетам взяты с сайта NASA: https://ssd.jpl.nasa.gov/horizons/app.html#/

Дата начальных данных: **22 октября 2026 года**. Координаты и векторы скоростей взяты относительно **Solar System Barycenter (0)**. В файле координаты переведены в метры, скорости — в **м/с**, массы — в кг. Компоненты z и vz обнулены для проекции в 2D. Точный час, шкала времени и полный заголовок запроса Horizons не предоставлены, поэтому точное воспроизведение исходного запроса пока невозможно. Информация об источнике относится к координатам, скоростям и массам.

Порядок: Sun, Mercury, Venus, Earth, Mars, Jupiter, Saturn, Uranus, Neptune

Движение рассчитывает наш явный Эйлер: 2D, без спутников, релятивистских поправок и контроля ошибки. За длительное время накапливается численная ошибка энергии и орбит.

## Визуализация результата CSV

Установить зависимости:

```sh
python -m pip install -r requirements.txt
python visualize.py output_coordinates.csv --out visualization --gif --frames 150 --names Sun Mercury Venus Earth Mars Jupiter Saturn Uranus Neptune
```

Скрипт читает сам CSV: поддерживает ; или запятую, с заголовком или без. Имена должны идти в порядке входных тел; без --names используются Body 1, Body 2 и т.д. Поэтому подходит и к файлу с именем ouput_coordinates.csv, если передать его путь явно.

Два вида: вся система и область ±2 а.е. для внутренних планет. Оси имеют одинаковый масштаб, положения остаются барицентрическими; начало координат обозначено крестом. Размеры маркеров условные. PNG показывает полные рассчитанные траектории. GIF показывает выбранные строки CSV с нарастающим следом; --frames ограничивает число кадров, сам расчёт не меняет. На годовом расчёте внешние планеты проходят лишь часть орбиты. Уже сохранены PNG и GIF для 365.25 суток, 8766 шагов, 8767 строк. Анимация не является анимацией истинных размеров планет.

## Ограничения минимального C-кода

Оставлены исходные формат чтения с пропуском z/vz и ограниченные проверки чисел. На случай ошибки создания потока процесс завершается целиком; все штатные и расчётные пути освобождают массивы после join. Для произвольного недоверенного ввода потребуются дополнительные проверки конечности, диапазонов и переполнений. Генератор выдаёт корректные входы в используемых диапазонах. Новых оптимизаций и лишних механизмов синхронизации в основной код не добавлено.
